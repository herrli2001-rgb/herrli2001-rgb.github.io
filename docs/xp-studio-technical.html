运营自动化工作台 / PRODUCT & ENGINEERING

XP Studio

为零基础运营，把模型接入、固定工作流与 Agent 调度提前准备好。

需求说明 · 功能架构 · 技术依据更新于 2026.11.04

01

产品问题与目标

面向零基础运营同学。首次连接 Agent 的路径复杂，日报与搜索词采集反复占用人工时间，营销表达也需要不断修改。产品将模型接入、固定工作流、Agent 调度和日常交付集中到本地工作台。

设计原则：固定、可确定的动作由程序执行；Agent 负责调度、监控和参与分析，用户处理需要本人登录、授权或判断的环节。

02

核心需求与业务结果

需求实现思路业务记录 / 边界
零基础接入内置 CC Switch，预埋 Codex / Claude Code 的接入路径；提供就近指南和监控入口。填写本人 API；内部接入地址不公开。1M 是客户端预设，实际模型能力由上游提供。
经营日报把分散采集步骤编排成固定 workflow，再由 Agent 调度与监控。创建者记录：约 1 小时手工采集，改为约 10 分钟后台完成。
说人话基于近 5,000 组零售营销表达整理不同表达风格。帮助调整表达，不将语料整理描述为已经完成基础模型微调。
搜索词通过 API 与预置采集程序获取热搜词和场景词，再交给 Agent 分析。创建者记录：40 分钟以上的人工整理，改为约 1 分钟采集。

上述耗时来自创建者的特定业务场景记录，受数据量、网络和运行环境影响；不代表本次重新做了性能基准测试。

03

本地工程技术栈

层次技术 / 模块职责
工作台界面HTML / CSS / JavaScript；web/ 下的模块界面。首页、日报、营销表达、搜索词与配置交互。
本地服务Python；ThreadingHTTPServer / BaseHTTPRequestHandler。模块路由、任务入口、本地文件与状态服务。
Agent 运行时Node.js / DeepSeek Harness 与工作台扩展。会话、工具调用与执行反馈；与固定业务程序协作。
工具连接MCP 服务与自动化工作模块。将业务能力暴露为可调度工具，处理采集与交付。
本地状态SQLite / JSON 原子写入；core.py、job_storage.py。配置、任务状态和本地记录。具体字段不在公开说明中展开。
Windows 分发Inno Setup 6 / LZMA2 / C# 配置辅助程序。单层安装、依赖配置、独立用户数据与卸载清理。

04

模块职责与执行路径

  1. 01选择业务目标

    确定日期、范围、任务类型与预期输出。

  2. 02固定 workflow

    采集、清洗、口径校验与文件生成由已有程序执行。

  3. 03Agent 监控与分析

    观察执行状态，识别异常，参与结果解释。

  4. 04本地交付与复核

    交付看板、文件和执行记录；需人工处理的事项明确反馈。

05

1.1 r2 安装工程复盘

本次提供的 ZIP 是基于原工程的安装优化补丁，内容聚焦发行、安装和卸载，不是完整业务源码，也不是可供用户安装的软件包。

原发布目录中的依赖链接被递归展开，造成安装文件数量膨胀。r2 改为从干净目录构建 payload、跳过目录链接、使用显式文件清单，并在构建前审计链接目标。

改动工程目的
干净 payload + 显式文件清单避免 junction / symlink 被安装器递归展开。
单层 EXE + LZMA2移除外层自解包壳，直接产出安装包。
内置 Obsidian 配置辅助已安装时复用，失败时保留诊断信息。
独立数据目录升级或卸载程序文件时保留用户数据。
隔离安装验证先安装到专用测试目录，再验证运行，避免污染发行目录。
