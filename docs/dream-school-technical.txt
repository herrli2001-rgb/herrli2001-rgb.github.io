Dream School｜需求与技术说明

整理日期：2026-10-29

文档性质：基于现有工程回溯整理，不是原始历史 PRD；以下验收项是标准，不代表本次已经执行。

作品状态：已上线，持续迭代（创作者确认）。

一、产品定义

开放世界校园生活与海岸探索

让玩家在校园日常与自由探索之间自主选择活动，同时让交通、天气与居民构成连续的世界。

目标用户：喜欢校园生活、轻量模拟与开放探索的玩家。

二、需求与优先级

P0 / 连贯探索：第三人称角色在校园、道路、海岸与室内场所之间移动，并获得明确的交互反馈。

P0 / 多种移动方式：步行、骑行、驾驶、轨道交通、飞行和潜水分别管理控制状态，切换时恢复正确的输入与相机。

P1 / 日常参与：课程、用餐、商店、对话与居民活动让地点具备可使用的功能。

P1 / 环境变化：日夜和天气改变场景表现，地表湿度与积雪随时间累计和衰减。

三、核心用户路径

进入校园 → 自由移动 → 观察交互提示 → 上课或与居民交流 → 选择交通 → 探索海岸 → 回到校园

四、技术栈

Godot 4.7 / GDScript / Forward Plus

五、模块职责

场景入口｜project.godot / main.tscn：指定主场景、分辨率、渲染与物理参数。

角色输入｜scripts/player.gd：管理移动、特殊移动与玩家状态；车辆和自行车由各自控制脚本承担。

交通｜vehicle.gd / bicycle.gd / transit.gd：按交通方式拆分控制职责，将移动模式接回同一世界。

居民与生活｜resident_plan.gd / student_routines.gd / npc_dialogue.gd：规则驱动的活动与对话，不将 NPC 误述为大语言模型角色。

环境｜weather.gd / weather_ground.gd：天气表现与地表累计状态分别维护，保留材质状态缓存。

重复几何｜crowd_batch.gd / transit_static_batch.gd：使用 MultiMesh / MultiMeshInstance3D 批量绘制重复几何。

六、状态与数据流

输入层 → 玩家或交通控制器 → 世界交互 → 居民 / 时间 / 天气规则 → 动作、材质与 UI 反馈

七、验收清单

待检查｜移动切换：从步行进入骑行、车辆或水域后，输入只交给当前控制器；退出后恢复角色状态。

待检查｜场所交互：进入教室、商店等区域时显示正确提示，重复操作不会叠加错误状态。

待检查｜天气持续性：降雨或积雪开始、持续、停止时，地表状态平滑累计与衰减。

待检查｜交通连贯性：交通工具沿设计路线运行，玩家进出与相机切换一致。

待检查｜性能验证：分别记录密集居民、交通与天气场景的 CPU/GPU 帧时间，按实际设备制定预算。

八、测试与证据

记录版本、设备、操作路径、预期、实际结果与复现素材。冒烟测试覆盖从进入游戏到核心体验完成；异常检查覆盖重复交互、切换状态和重新载入。性能采样分别观察 CPU 与 GPU 帧时间。

已有工程截图、原始实机录屏和宣传片作为展示证据，不替代功能验收报告。

九、限制与后续

工程配置包含 max_fps=120、物理 60Hz、MSAA 3D=1；这些是配置值，不能作为稳定 120 FPS 的实测结论。宣传海报与游戏实机已分别标注；素材包含第三方资源。
